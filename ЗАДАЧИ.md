# ЗАДАЧИ — анализ проекта «ОС Чёрное Море»

Разбор конфигурации ядра, скриптов сборки и rootfs. Отсортировано по важности.
Дата анализа: 2026-08-29.

---

## 🔴 Критично — ломает функциональность

### 1. Драйверы ядра собраны как модули (`=m`), но модули нигде не устанавливаются
- В `.config` **5034** опций как `=m`, при этом `make modules_install` нет ни в
  `основа.c`, ни в скриптах, а `rootfs/lib64/modules` пуст. Значит **все `=m`
  драйверы недоступны** в работающей системе.
- Конкретные поломки:
  - `CONFIG_INPUT_EVDEV=m` → нет `/dev/input/event*` → **weston / libinput без
    клавиатуры и мыши**.
  - `CONFIG_VFAT_FS=m` → монтирование `/boot` из `fstab` падает (нет FS).
  - `CONFIG_USB_HID=m`, `CONFIG_HID_GENERIC=m`, `CONFIG_MOUSE_PS2=m`,
    `CONFIG_INPUT_MOUSEDEV=m` → нет ввода с USB / PS2 на реальном железе.
  - Все GPU-DRM (`I915/AMDGPU/NOUVEAU/VIRTIO_GPU/QXL/BOCHS=m`), а для VirtualBox
    (VMSVGA) драйвера `VMWGFX` вообще нет → **weston `drm-backend`/`gl-renderer`
    без реального GPU** (только программный `simpledrm`, которого weston для
    modesetting обычно недостаточно).
- **Решение (выбрать одно):**
  - (A) Перевести нужное в `=y`: `INPUT_EVDEV`, `VFAT_FS` + `NLS_*`, `USB_HID`,
    `HID_GENERIC`, `MOUSE_PS2`, `INPUT_MOUSEDEV`, нужный GPU-DRM (`DRM_VMWGFX`
    для VBox / `DRM_VIRTIO_GPU` для QEMU), остальное — вырезать. Проще, без
    инфраструктуры модулей.
  - (B) Добавить шаг `make modules_install INSTALL_MOD_PATH=<rootfs>` + `depmod`,
    и `modprobe` нужных модулей в init. Тяжелее.

### 2. `CONFIG_MODULE_SIG_FORCE=y` при драйверах-модулях
- Даже если установить модули (вариант 1B), без цифровой подписи ядро их
  **не загрузит**. Для хобби-дистро — лишний барьер.
- **Решение:** либо отключить `MODULES`/`MODULE_SIG_FORCE` целиком (если всё `=y`),
  либо настроить подпись модулей ключом сборки.

### 3. `.gitignore` игнорирует `*.so` и `*.so.*`
- Библиотеки weston в `rootfs/lib64`, `rootfs/usr`, а также `libkonda-transpiler.so`
  **не попадают в git**. Рабочий процесс «закинуть weston в дистрибутив» не
  сохраняется в репозитории.
- **Решение:** добавить исключение для rootfs, например:
  ```gitignore
  !rootfs/**
  ```
  (или точечно `!rootfs/**/*.so*`), поместив после правил `*.so`.

### 4. `основа.c` кладёт `.so` в `rootfs/lib` — загрузчик его не ищет
- Функция `установить_из_собранное()` копирует `*.so` в `../../rootfs/lib`, но
  загрузчик дистрибутива ищет только в `/lib64` и `/usr/lib64` (проверено:
  `ld-linux --help`, `ld.so.cache` нет). Поэтому `libkonda-transpiler.so`
  в `/lib` **невидим в рантайме** — та же причина, по которой не стартовал weston.
- Заодно классификация по суффиксу `.so` не ловит `.so.N` (уедет в `bin`).
- **Решение:** менять целевой путь на `rootfs/lib64` и матчить `\.so` в любом месте
  имени (`.so`, `.so.1` …).

## 🟠 Важно — ошибки конфигурации и хрупкость

### 5. `fstab`: неверный идентификатор /boot
- `PARTUUID=77A7-77A7  /boot  vfat` — `77A7-77A7` это **FAT-serial (том)**, а не
  PARTUUID; корректно `UUID=77A7-77A7`. И `vfat=m` → монтирование всё равно
  падает (см. п.1). Само монтирование ESP в `/boot` для загрузки не требуется
  (ядро грузит firmware напрямую из ESP).
- **Решение:** `UUID=77A7-77A7` + `VFAT_FS=y`, либо убрать строку `/boot`.

### 6. Три расходящихся источника cmdline
- Вшитый `CONFIG_CMDLINE` = `console=tty0 … root=PARTUUID=12345678-… quiet loglevel=7`
  (без `init=`), а `startup.nsh` и `cmdline.txt` = `console=ttyS0,115200 … init=/init`.
- При автозагрузке `EFI/BOOT/BOOTX64.EFI` firmware **не передаёт** аргументы →
  используется вшитый `CONFIG_CMDLINE`, а `startup.nsh`/`cmdline.txt` фактически
  мертвы (работают только через EFI Shell). `CMDLINE_OVERRIDE` отключён.
- **Решение:** свести к одному источнику истины (вшитый `CONFIG_CMDLINE`),
  согласовать `console=` (для GUI VBox нужен `tty0`, `ttyS0` — только с сериал-портом).

### 7. `quiet loglevel=7` противоречивы
- `loglevel=7` отменяет `quiet`. Выбрать одно (для тихой загрузки — `quiet`
  без `loglevel`, для диагностики — `loglevel=7` без `quiet`).

### 8. `создать_образ.sh`: PARTUUID ESP не совпадает (варнинг в логе)
- `BOOT_PARTUUID="77A7-77A7"` используется в двух несовместимых ролях: как
  FAT-serial (`mkfs.vfat -i`) и как GPT partition GUID (`sgdisk --partition-guid`),
  где `sgdisk` разворачивает его в `77a7f97a-0000-…` → warning «PARTUUID не совпадает».
- **Решение:** развести две переменные — `ESP_FAT_SERIAL=77A7-77A7` и
  отдельный полноценный `ESP_PART_GUID=<полный-UUID>`.

## 🟡 Улучшения

### 9. `update-kernel.sh` не синхронизирует конфиг с новой версией
- После checkout нового тега ядра нет `make olddefconfig` — `.config` от старой
  версии может рассинхронизироваться (новые символы останутся дефолтными).
- **Решение:** после обновления прогонять `make olddefconfig` (и, при желании,
  `strip-config.sh`).

### 10. Ускорить сборку ядра
- 5034 модуля = очень долгая сборка и гигабайты артефактов, которые не
  устанавливаются. `make localmodconfig` на целевой машине или ручной minimal
  defconfig резко ускорят и уменьшат `bzImage`.

### 11. `основа.c`: копирование теряет права доступа
- `копировать_файл()` пишет через `fopen("wb")` — новому файлу назначается `0644`
  (не исполняемый). Сейчас работает только потому, что `rootfs/sbin/init` уже
  существует с `+x` (fopen не меняет права существующего файла). На чистом
  rootfs init/бинарники окажутся без `+x`.
- **Решение:** после копирования выставлять `chmod 0755` для init и бинарников
  (или копировать с сохранением режима).

### 12. `конвертировать_образ.sh` без защиты от отсутствия .img
- При отсутствии `.img` `cp … .старый` и конвертация падают неинформативно; нет
  проверки, что образ свежее исходников.
- **Решение:** проверять наличие `.img` в начале, понятная ошибка.

### 13. Нет tmpfs для `/run` и `/tmp`
- weston требует `XDG_RUNTIME_DIR` (обычно `/run/user/0`, режим `0700`).
  В `fstab` монтируются только `proc` и `sys`; `/run` и `/tmp` не создаются.
- **Решение:** добавить в fstab (или init) tmpfs на `/run` и `/tmp`, экспортировать
  `XDG_RUNTIME_DIR`.

### 14. `xkbcommon`-данные для weston
- `libxkbcommon` в рантайме читает раскладки из `xkeyboard-config`
  (`/usr/share/X11/xkb`). Для weston их нужно докинуть в rootfs.

## ⚪ Мелочи / безопасность

### 15. root без пароля
- `passwd`: `root:x:0:0:root:/root:/bin/sh`, но `/etc/shadow` нет → вход без
  пароля. Для локального образа приемлемо, но стоит осознавать.

### 16. `my_vars.fd` (OVMF NVRAM) в репозитории
- Файл переменных UEFI специфичен для машины — стоит вынести из репо или
  добавить в `.gitignore`.

### 17. README не описывает `добавить_программу.sh`
- Не задокументированы скрипт добавления программ и требование совместимости
  glibc для внешних бинарников (weston собран под системный glibc; при
  необходимости `добавить_программу.sh` обновляет glibc в rootfs).
